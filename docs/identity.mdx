On the desk you will see a button labeled **Desk ID**. Tap it and you copy a long code. That code is how Tally knows which person a loan is talking about when you make an offer.

Your **Lace** or **1AM** wallet is a different tool. Lace and 1AM are browser wallets for Midnight. They hold test tokens, pay fees, and show a popup so you can approve a transaction. A **transaction** is a signed change sent to the network. Think of the wallet as the pen that signs the paper. Desk ID is the name written on the paper.

When a lender makes an offer on Preprod, they paste the borrower’s Desk ID into the form. If that code is wrong, the wrong browser cannot accept. If it matches, the right person can.

## How the desk builds a Desk ID

The real key is a browser secret. The desk saves it in localStorage under the key `tally-midnight-secret`. Whoever copies that secret can act as that Desk ID.

The number `1234` is a fixed public mix-in in the Desk ID hash. It is a domain tag in the code, not a password anyone types. The desk never asks for it. The same secret and the same mix-in always make the same Desk ID. A different browser profile usually has a different secret. That is why a two-person demo often uses two Chrome profiles on one machine.

The wallet only pays fees. Lace or 1AM is not the Desk ID.

## What you paste into Borrower id

On Preprod, the Offer form asks for **Borrower id**. Paste the other person’s Desk ID (64 hex characters). Do not paste a Lace payment address that starts like `mn_addr_`.

On Local desk, the demo already knows the built-in borrower. The Borrower id field stays hidden.

## Relationship leaf (for standing)

When a loan **Settles**, the contract adds a **relationship leaf**. That is a sealed mark made from the loan id and both people’s Desk IDs. Later, **Prove standing** rebuilds that mark in private and checks it sits in the allowlist tree. The verifier never sees which leaf you used. They only see Pass or Fail.
